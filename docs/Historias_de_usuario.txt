2. REGLAS DE NEGOCIO
────────────────────────────────────────────────────────────────────────────────

DOMINIO: AUTENTICACIÓN Y ACCESO

  RN-01  Cada usuario debe tener exactamente un rol: admin, preceptor, docente
         o padre. No se permiten roles múltiples.

  RN-02  Un usuario con is_active = false no puede autenticarse en el sistema,
         aunque proporcione credenciales correctas.

  RN-03  Un padre solo puede acceder a los datos de los alumnos que tenga
         explícitamente vinculados en la tabla parent_student. El acceso a
         datos de otros alumnos debe ser denegado con HTTP 403.

  RN-04  Un docente solo puede cargar, editar o eliminar calificaciones y tareas
         de las materias que tenga asignadas en la tabla teacher_subject.
         Intentar operar sobre materias no asignadas devuelve HTTP 403.

DOMINIO: ASISTENCIAS

  RN-05  Solo puede existir un registro de asistencia por alumno por fecha
         (unicidad en la combinación student_id + date). Intentar crear un
         segundo registro para el mismo par devuelve HTTP 409.

  RN-06  Solo un preceptor o administrador puede registrar o modificar el estado
         de una inasistencia. Los docentes y padres tienen acceso de solo lectura.

  RN-07  Una inasistencia justificada no puede revertirse a no justificada.
         La justificación es una operación de solo ida.

  RN-08  La carga de un certificado de justificación admite únicamente archivos
         de tipo image/jpeg, image/png o application/pdf, con un tamaño máximo
         de 5 MB. Archivos que no cumplan estas condiciones deben ser rechazados
         antes de ser procesados.

  RN-09  El sistema debe mantener y exponer un resumen de asistencia por alumno
         que incluya: total de días registrados, total de ausencias, ausencias
         justificadas y ausencias no justificadas.

DOMINIO: CALIFICACIONES

  RN-10  Una calificación debe tener un valor numérico entre 1,00 y 10,00
         (inclusive). Valores fuera de este rango son rechazados por validación.

  RN-11  Cada calificación debe estar asociada a un período académico válido:
         1er_trimestre, 2do_trimestre, 3er_trimestre o recuperatorio.

  RN-12  El docente que creó una calificación es el único que puede editarla o
         eliminarla, a excepción del administrador que tiene permiso universal.

DOMINIO: TAREAS

  RN-13  Una tarea solo puede ser creada por el docente asignado a la materia
         correspondiente. La fecha de vencimiento (due_date) no puede ser
         anterior a la fecha de creación.

  RN-14  El sistema crea automáticamente un registro task_submission con estado
         'pendiente' para cada alumno del curso al momento de crear una tarea.
         Este proceso debe ejecutarse de forma atómica (todo o nada).

  RN-15  El estado de una entrega solo puede avanzar según la máquina de estados
         definida: pendiente → entregada | pendiente → tarde.
         No se permite retroceder de entregada a pendiente.

DOMINIO: NOTIFICACIONES

  RN-16  El agente automatizado no enviará una notificación del mismo tipo para
         el mismo alumno más de una vez por día, para evitar spam sobre el mismo
         evento.

  RN-17  Cada notificación enviada (exitosa o fallida) debe quedar registrada en
         la tabla notification_logs para auditoría del administrador.

  RN-18  El umbral de inasistencias que activa la alerta AUSENCIAS_CRITICAS es
         configurable por el administrador (valor por defecto: 10 ausencias no
         justificadas en el ciclo).

DOMINIO: LICENCIAS DOCENTES

  RN-19  Solo el administrador puede aprobar o rechazar una licencia. El docente
         puede solicitarla pero no puede modificar su estado.

  RN-20  La fecha de fin de una licencia no puede ser anterior a la fecha de
         inicio. El sistema debe calcular automáticamente los días_used al
         crear el registro.

ÉPICA 1: AUTENTICACIÓN Y GESTIÓN DE SESIÓN
══════════════════════════════════════════════════

────────────────────────────────────────────────────────────────────────────────
ID            : US-001
Título        : Inicio de sesión
Historia      : Como usuario del sistema (cualquier rol), quiero iniciar sesión
                con mi email y contraseña, para acceder a las funcionalidades
                correspondientes a mi rol.
Prioridad     : Alta
Dependencias  : Ninguna
Criterios de aceptación:
  GIVEN un usuario con credenciales válidas y cuenta activa
  WHEN envía email y contraseña al formulario de login
  THEN recibe un JWT válido y es redirigido al dashboard de su rol

  GIVEN un usuario con credenciales incorrectas
  WHEN envía email o contraseña erróneos
  THEN recibe un mensaje de error "Credenciales inválidas" y no obtiene token

  GIVEN un usuario con cuenta desactivada (is_active: false)
  WHEN intenta iniciar sesión con credenciales correctas
  THEN recibe un mensaje de error y no puede acceder al sistema

Notas técnicas: POST /api/v1/auth/login. JWT almacenado en memoria (Context API)
                o localStorage según decisión del equipo. Tabla: users.
────────────────────────────────────────────────────────────────────────────────

────────────────────────────────────────────────────────────────────────────────
ID            : US-002
Título        : Cierre de sesión
Historia      : Como usuario autenticado, quiero cerrar mi sesión de forma
                explícita, para proteger mi información en dispositivos
                compartidos.
Prioridad     : Alta
Dependencias  : US-001
Criterios de aceptación:
  GIVEN un usuario autenticado
  WHEN hace clic en "Cerrar sesión"
  THEN el token es eliminado del estado cliente y es redirigido al login

  GIVEN un usuario que cerró sesión
  WHEN intenta acceder a una ruta protegida con el token anterior
  THEN es redirigido al login (token inválido o eliminado del cliente)

Notas técnicas: POST /api/v1/auth/logout. El token se invalida del lado cliente.
