──────────────────────────────
ENTIDAD: users
──────────────────────────────
  id              SERIAL PRIMARY KEY
  email           VARCHAR(255) NOT NULL UNIQUE
  password_hash   VARCHAR(255) NOT NULL
  role            ENUM('admin','preceptor','docente','padre') NOT NULL
  first_name      VARCHAR(100) NOT NULL
  last_name       VARCHAR(100) NOT NULL
  phone_whatsapp  VARCHAR(20)               -- para notificaciones Twilio
  is_active       BOOLEAN DEFAULT true
  created_at      TIMESTAMP DEFAULT NOW()
  updated_at      TIMESTAMP DEFAULT NOW()

──────────────────────────────
ENTIDAD: students
──────────────────────────────
  id              SERIAL PRIMARY KEY
  first_name      VARCHAR(100) NOT NULL
  last_name       VARCHAR(100) NOT NULL
  dni             VARCHAR(20) UNIQUE
  birth_date      DATE
  course_id       INTEGER FK → courses(id)
  is_active       BOOLEAN DEFAULT true
  created_at      TIMESTAMP DEFAULT NOW()
  updated_at      TIMESTAMP DEFAULT NOW()

──────────────────────────────
ENTIDAD: parent_student  (tabla de unión N:M)
──────────────────────────────
  id              SERIAL PRIMARY KEY
  user_id         INTEGER FK → users(id)     -- rol: padre
  student_id      INTEGER FK → students(id)
  relationship    VARCHAR(50)                -- 'madre','padre','tutor', etc.
  UNIQUE(user_id, student_id)

──────────────────────────────
ENTIDAD: courses
──────────────────────────────
  id              SERIAL PRIMARY KEY
  name            VARCHAR(100) NOT NULL      -- ej: "3° A"
  year            INTEGER NOT NULL           -- ciclo lectivo
  division        VARCHAR(10)
  level           VARCHAR(50)                -- ej: "Secundaria"
  created_at      TIMESTAMP DEFAULT NOW()

──────────────────────────────
ENTIDAD: subjects
──────────────────────────────
  id              SERIAL PRIMARY KEY
  name            VARCHAR(100) NOT NULL      -- ej: "Matemática"
  course_id       INTEGER FK → courses(id)
  created_at      TIMESTAMP DEFAULT NOW()

──────────────────────────────
ENTIDAD: teacher_subject  (tabla de unión N:M)
──────────────────────────────
  id              SERIAL PRIMARY KEY
  user_id         INTEGER FK → users(id)     -- rol: docente
  subject_id      INTEGER FK → subjects(id)
  UNIQUE(user_id, subject_id)

──────────────────────────────
ENTIDAD: grades
──────────────────────────────
  id              SERIAL PRIMARY KEY
  student_id      INTEGER FK → students(id)
  subject_id      INTEGER FK → subjects(id)
  teacher_id      INTEGER FK → users(id)
  value           DECIMAL(4,2) NOT NULL      -- ej: 7.50
  period          ENUM('1er_trimestre','2do_trimestre','3er_trimestre','recuperatorio')
  grade_date      DATE NOT NULL
  notes           TEXT                       -- observaciones opcionales
  created_at      TIMESTAMP DEFAULT NOW()
  updated_at      TIMESTAMP DEFAULT NOW()

──────────────────────────────
ENTIDAD: attendances
──────────────────────────────
  id              SERIAL PRIMARY KEY
  student_id      INTEGER FK → students(id)
  date            DATE NOT NULL
  status          ENUM('presente','ausente','tarde') NOT NULL
  is_justified    BOOLEAN DEFAULT false
  justification_note TEXT
  certificate_url VARCHAR(500)               -- URL del certificado subido
  registered_by   INTEGER FK → users(id)    -- preceptor que registró
  created_at      TIMESTAMP DEFAULT NOW()
  updated_at      TIMESTAMP DEFAULT NOW()
  UNIQUE(student_id, date)

──────────────────────────────
ENTIDAD: tasks
──────────────────────────────
  id              SERIAL PRIMARY KEY
  title           VARCHAR(255) NOT NULL
  description     TEXT
  subject_id      INTEGER FK → subjects(id)
  teacher_id      INTEGER FK → users(id)
  due_date        DATE NOT NULL
  created_at      TIMESTAMP DEFAULT NOW()
  updated_at      TIMESTAMP DEFAULT NOW()

──────────────────────────────
ENTIDAD: task_submissions
──────────────────────────────
  id              SERIAL PRIMARY KEY
  task_id         INTEGER FK → tasks(id)
  student_id      INTEGER FK → students(id)
  status          ENUM('pendiente','entregada','tarde') DEFAULT 'pendiente'
  submitted_at    TIMESTAMP
  notes           TEXT
  created_at      TIMESTAMP DEFAULT NOW()
  updated_at      TIMESTAMP DEFAULT NOW()
  UNIQUE(task_id, student_id)

──────────────────────────────
ENTIDAD: teacher_leaves  (licencias docentes)
──────────────────────────────
  id              SERIAL PRIMARY KEY
  user_id         INTEGER FK → users(id)     -- rol: docente
  leave_type      VARCHAR(100)               -- ej: "Enfermedad","Personal","Gremial"
  start_date      DATE NOT NULL
  end_date        DATE NOT NULL
  days_used       INTEGER NOT NULL
  status          ENUM('pendiente','aprobada','rechazada') DEFAULT 'pendiente'
  approved_by     INTEGER FK → users(id)    -- admin que aprobó
  notes           TEXT
  created_at      TIMESTAMP DEFAULT NOW()
  updated_at      TIMESTAMP DEFAULT NOW()

──────────────────────────────
ENTIDAD: notification_logs  (auditoría del agente)
──────────────────────────────
  id              SERIAL PRIMARY KEY
  recipient_id    INTEGER FK → users(id)
  student_id      INTEGER FK → students(id)
  type            VARCHAR(100)               -- ej: "AUSENCIAS_CRITICAS"
  message         TEXT
  channel         VARCHAR(50) DEFAULT 'whatsapp'
  status          ENUM('enviado','fallido') NOT NULL
  sent_at         TIMESTAMP DEFAULT NOW()

6. PATRONES DE DISEÑO — EJEMPLOS DE REFERENCIA

── Repository Pattern ──────────────────────────────────────────────────────────

  // src/repositories/gradeRepository.js
  const { Grade } = require('../models');

  const gradeRepository = {
    async findByStudent(studentId, filters = {}) {
      return Grade.findAll({
        where: { student_id: studentId, ...filters },
        order: [['grade_date', 'DESC']]
      });
    },
    async create(data) {
      return Grade.create(data);
    },
    async update(id, data) {
      const [count, rows] = await Grade.update(data, {
        where: { id }, returning: true
      });
      return rows[0];
    }
  };
  module.exports = gradeRepository;

── Service Layer Pattern ───────────────────────────────────────────────────────

  // src/services/gradeService.js
  const gradeRepository = require('../repositories/gradeRepository');
  const teacherSubjectRepository = require('../repositories/teacherSubjectRepository');
  const AppError = require('../utils/AppError');

  const gradeService = {
    async createGrade(teacherId, gradeData) {
      const isAssigned = await teacherSubjectRepository.exists(
        teacherId, gradeData.subject_id
      );
      if (!isAssigned) {
        throw new AppError('No tenés asignada esta materia', 403);
      }
      return gradeRepository.create({ ...gradeData, teacher_id: teacherId });
    }
  };
  module.exports = gradeService;

── Protected Route (Frontend) ──────────────────────────────────────────────────

  // src/routes/ProtectedRoute.jsx
  import { useContext } from 'react';
  import { Navigate } from 'react-router-dom';
  import { AuthContext } from '../context/AuthContext';

  const ProtectedRoute = ({ children, allowedRoles }) => {
    const { user } = useContext(AuthContext);
    if (!user) return <Navigate to="/login" />;
    if (!allowedRoles.includes(user.role)) return <Navigate to="/unauthorized" />;
    return children;
  };
  export default ProtectedRoute;

7. CONFIGURACIÓN DE SEGURIDAD
────────────────────────────────────────────────────────────────────────────────

JWT
  - Algoritmo       : HS256
  - Expiración      : 8h (sesión de jornada escolar)
  - Payload         : { id, role, email, iat, exp }
  - Secreto         : variable de entorno JWT_SECRET (mínimo 32 caracteres)
  - Refresh         : No implementado en MVP. Considerar para fase 2.

CORS
  - Origen permitido : dominio del frontend en producción (Vercel URL)
  - Métodos          : GET, POST, PUT, DELETE, OPTIONS
  - Headers          : Content-Type, Authorization

RATE LIMITING
  - Librería         : express-rate-limit
  - Límite global    : 100 requests / 15 min por IP
  - Límite /auth/login: 10 intentos / 15 min por IP (prevención de fuerza bruta)

HASHING DE CONTRASEÑAS
  - Librería  : bcrypt
  - Rounds    : 12

VALIDACIÓN DE INPUTS
  - Librería  : express-validator o Joi
  - Aplicar en: todos los endpoints POST y PUT antes de llegar al controller

VARIABLES DE ENTORNO (nunca en el repositorio)
  DATABASE_URL      PostgreSQL connection string
  JWT_SECRET        Clave secreta para firmar tokens
  TWILIO_ACCOUNT_SID
  TWILIO_AUTH_TOKEN
  TWILIO_WHATSAPP_FROM
  CLOUDINARY_URL    (si se usa para almacenamiento de certificados)
  SERVICE_API_KEY   Clave para el endpoint interno del agente Python

SUBIDA DE ARCHIVOS (certificados)
  - Solo se aceptan archivos de tipo: image/jpeg, image/png, application/pdf
  - Tamaño máximo   : 5 MB por archivo
  - Los archivos se almacenan en un servicio de storage externo (Cloudinary
    o Railway Volume), nunca en el servidor de la aplicación.

8. LÓGICA DEL AGENTE AUTOMATIZADO (Python)
────────────────────────────────────────────────────────────────────────────────

El agente se ejecuta periódicamente (una vez por día, al finalizar la jornada
escolar) y realiza las siguientes evaluaciones contra la base de datos:

  ALERTA 1 — AUSENCIAS_CRITICAS
    Condición : El alumno acumuló ≥ X inasistencias no justificadas en el ciclo
                (X es configurable, valor por defecto: 10).
    Destinatario: Padre/tutor del alumno.
    Mensaje   : "Su hijo/a [nombre] acumula [N] inasistencias no justificadas.
                Comuníquese con la institución."

  ALERTA 2 — RIESGO_REGULARIDAD
    Condición : El alumno tiene ≥ 20% de inasistencias sobre el total de clases
                dictadas en el trimestre activo.
    Destinatario: Padre/tutor del alumno.

  ALERTA 3 — CALIFICACION_BAJA
    Condición : Se registró una calificación < 4 (reprobado) para un alumno.
    Destinatario: Padre/tutor del alumno.

  ALERTA 4 — TAREA_PENDIENTE
    Condición : Una tarea vence en ≤ 2 días y el alumno no registra entrega.
    Destinatario: Padre/tutor del alumno.

  ALERTA 5 — LICENCIA_DOCENTE_VENCIMIENTO
    Condición : Una licencia docente aprobada vence en ≤ 3 días.
    Destinatario: Docente afectado y administrador.

  Para cada alerta disparada, el agente registra un log en la tabla
  notification_logs con el estado del envío (enviado/fallido).
