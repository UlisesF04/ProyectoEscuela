--------------------------------------------------------------------------------
1. VISIÓN GENERAL DE LA ARQUITECTURA
--------------------------------------------------------------------------------

    El sistema está dividido en seis capas principales:

    [x] FRONTEND (React + Vite + Chakra UI)  ←→  BACKEND (Node/Express)
    [x]              │                                    │
    [x]         PostgreSQL (única fuente de verdad)       │
    [x]              │                                    │
    [x]    AGENTE PYTHON (Bot + OpenSpec)                 │
    [x]              │                                    │
    [x]    WhatsApp API (provider TBD)                    │
    [x]                                                    │
    [x]    Servicio externo de archivos (Cloudinary) ←────┘

    Cada capa es independiente y se comunica mediante interfaces definidas
    (API REST para frontend↔backend; conexión directa a PostgreSQL para el
    agente; almacenamiento externo para certificados).

--------------------------------------------------------------------------------
2. TECNOLOGÍAS DEFINIDAS EN EL PROYECTO
--------------------------------------------------------------------------------

    ── FRONTEND ──────────────────────────────────────────────────────────────

    React.js (v19)
        [ ] Framework principal. Componentes funcionales + hooks.
        [ ] Estructura: components/, pages/, hooks/, services/, context/, utils/.

    Vite (v8)
        [ ] Build tool y servidor de desarrollo. HMR rápido.

    Chakra UI (v3)
        [ ] Librería de componentes accesibles. Sistema de diseño definido en
            `theme.js` (colores: azul institucional, verde éxito, gris neutro).

    React Router (v7)
        [ ] Enrutamiento del lado del cliente. Rutas protegidas según rol.

    Recharts / Chart.js
        [ ] Biblioteca de gráficos para el tablero de analítica.
        [ ] Gráficos de líneas (evolución de notas), barras apiladas
            (asistencias justificadas vs no justificadas).

    Context API + AuthContext
        [ ] Estado global de autenticación y perfil.

    Axios
        [ ] Cliente HTTP con interceptor para adjuntar JWT.

    ── BACKEND ────────────────────────────────────────────────────────────────

    Node.js (v20 LTS)
        [ ] Runtime del servidor.

    Express.js
        [ ] Framework web. Rutas modulares por dominio:
            auth, absences, grades, tasks, teachers, tutors, analytics, communication, certificates.

    Sequelize ORM
        [ ] Modelos, migraciones y relaciones.
        [ ] Nuevos modelos: Certificado, MensajeInterno, Inasistencia (extendido).

    JSON Web Token (JWT)
        [ ] Autenticación stateless con roles embebidos (admin, docente, preceptor, tutor).

    Multer / Cloudinary (o similar)
        [ ] Subida de archivos (certificados) al almacenamiento externo.
        [ ] En la base de datos se guarda la URL devuelta.

    ── BASE DE DATOS ──────────────────────────────────────────────────────────

    PostgreSQL (v16)
        [ ] Base de datos relacional principal.
        [ ] Nuevas tablas:
            - certificados (id, alumno_id, archivo_url, estado, comentario, timestamps)
            - mensajes_internos (id, emisor_id, receptor_id, texto, leido, respondido)
        [ ] Extensión de tabla inasistencias: justificada (boolean), certificado_id (FK)

    ── AGENTE AUTOMATIZADO (PYTHON + OPENSPEC) ─────────────────────────────────

    Python (v3.12)
        [ ] Lenguaje del agente.

    psycopg2-binary
        [ ] Conector directo a PostgreSQL.

    python-dotenv
        [ ] Manejo de variables de entorno.

    schedule
        [ ] Ejecución periódica (cada 1 hora en ventana hábil).

    OpenSpec (wrapper manual)
        [ ] El agente lee un spec YAML con tools declaradas y las mapea a funciones Python.

    WhatsApp API (provider TBD: Twilio o Meta Business)
        [ ] Envío de notificaciones. Credenciales en .env.

    ── INFRAESTRUCTURA Y DEVOPS ────────────────────────────────────────────────

    Vercel
        [ ] Despliegue frontend.

    Railway / Render
        [ ] Despliegue backend + PostgreSQL + worker Python.

    Cloudinary
        [ ] Almacenamiento de certificados (o bucket S3).

    GitHub
        [ ] Control de versiones. Branch strategy: main, develop, feature/*.

    Variables de entorno (.env)
        [ ] Secretos: DB, JWT, WhatsApp API, Cloudinary.

3. TECNOLOGÍAS EN USO CON OPENSPEC / AGENTES IA
--------------------------------------------------------------------------------

    OpenSpec Framework (planificado)
        [ ] El agente Python se comporta como un agente IA con tools definidas
            en `openspec/specs/agent-notifier/spec.yaml`.
        [ ] Tools: consultar_inasistencias, consultar_calificaciones_criticas,
            consultar_tareas_pendientes, consultar_licencias, enviar_notificacion.
        [ ] El scheduler invoca el spec y las tools ejecutan lógica real.

    Estado actual:
        [~] Definición del spec en progreso.
        [ ] Mapeo tools → funciones Python.
        [ ] Tests del agente con mock de DB y notificador.
